- THE MOST IMPORTANT RULE IS: when making changes, ONLY MAKE THE MINIMIMAL AMOUNT OF CHANGES REQUIRED TO FULFILL THE PROMPT'S REQUEST. Do not make refactoring changes unless requested. Do not make any changes to whitespaces, naming conventions, or other aesthetically related changes unless requested specifically by the prompt. 
- never perform code edits using grep, or find/replace. 
- always make code changes one at a time, and take into consieration code semantics to avoid stupid bugs
- code should be inlined, unless it is used more than once. If it is used more than once, it should be extracted out to a function or method. Similar code that is not identical but close enough to be reusable through parameters should also be extracted out into a separate function or method.
- methods that are shared accross different classes or files should be extracted out into a third, shared, common library for all files/classes to reuse.
- avoid creating alias functions for the purpose of backwards compatiblity. If a function or method is renamed, all references should be tracked down and renamed as well, instead of creating aliased functions to avoid that work.
- avoid creating wrapper functions for the purpose of backwards compatibility. If a function or method is moved to a different file or class, all references and imports should be tracked down and updated as well, instead of creating wrapper functions to avoid that work.
- when defining a multiple-option parameter or variable, instead of supporting multiple versions of the same value (for example "train", "training", "tr", etc) we should define enums or constants so that the values are always the same and always deterministic (for example OPTION_TRAIN = "train" and we import it and pass it along everywhere).
- always ensure all import declarations are at the begining of the file. Do not declare imports as part of methods or functions or anywhere else in a file.
- Whenever you add code that relies on a new library, make sure the library is added to the requirements.txt file. If a requirements.txt file does not exist at the root level of a project, create one and add all the libraries that are currently being used by all the files in the project.
- Whenever a missing library error exists, install the library in either the environment being used by the current project/folder, or the global python environment (if no specific environment is being used by the current project/folder). Do NOT add code that dynamically loads a library to avoid compile time errors because that will delay the problem until the runtime.
